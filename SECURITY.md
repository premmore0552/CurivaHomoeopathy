# Security policy

## Reporting a vulnerability

Please do not disclose suspected vulnerabilities in public issues, discussions, pull requests or social media.

Use GitHub's **Private vulnerability reporting** for this repository if it is enabled: open the repository's Security tab and choose Report a vulnerability. If that option is unavailable, contact the repository owner privately through their verified GitHub account and request a private reporting channel; do not attach patient records, credentials or real user data.

## What to include

Provide a concise description, affected route/component, impact, reproduction steps using a disposable test account and synthetic data, and any suggested remediation. Never include real patient details, payment-card details, access tokens, API keys or private customer files.

## Response and disclosure

The maintainers should acknowledge reports, reproduce them in an isolated environment, assess severity, coordinate a fix and release, rotate exposed secrets where needed, and agree a disclosure timeline with the reporter. Do not perform destructive testing, access other users' data or disrupt production.

This policy is a reporting process, not a guarantee of a particular response time or a statement that Curiva has undergone an independent security audit.
